**原因**: Apple Silicon 版を Intel Mac で実行  
**対応**: `ARIAKE_OCTA_macOS_Intel_v1.2.1.zip` を再送。別 PC でビルドした Intel 版が有効だった事例あり（木住野先生 ID:004）

**補足**: Intel Mac 初回起動は 90 秒程度かかることがある

#### 症状: メールがバウンス

**対応**:
- 履歴の「正」メールと「旧・エラー」メールを分けて記録

#### 症状: Mac で起動直後に問題レポート / 小ポップアップ（ログイン画面まで到達しない）

**瀧澤型（Connection Error）とは別。** ログイン UI が出る前に macOS がプロセスを SIGKILL する。

**原因（v1.2.3-mac・2026-08 前原先生 M3 で確定）:** PyInstaller の `collect_all(fastapi|uvicorn|…)` が `Contents/Frameworks/*.dist-info` を同梱。`codesign --deep` が `fastapi-0.110.0.dist-info` 等で **bundle format unrecognized** となり署名が壊れる → 起動時 **CODESIGNING Code 2 Invalid Page**（ARM-64 Native でも同じ。**Intel 混入は不要条件**）。

**対応:**
1. ターミナルで codesign した際に `fastapi-…dist-info` エラーが出ていれば、**ユーザー側再署名では直らない**。
2. **v1.2.4-mac 以降の ZIP を再送**（ビルド時に dist-info 除去 + ad-hoc 署名済み）。Windows 版は案内しない。
3. Gatekeeper 初回ブロックだけの場合は右クリック `インストール.command` で足りるが、**前原型は dist-info が主因**。

**実績:** 前原裕亮先生（ID:011、九州大学）— M3 / macOS 14.6.1 / v1.2.3-mac / 2026-08-31

---

#### 症状: ログインで「Connection Error: All connection attempts failed」

**前提: ログイン画面まで到達していること**（起動前 SIGKILL の場合は上節）。

**原因（認証失敗ではない）**: ログイン画面の UI は出ているが、同じ PC 内の解析エンジン（FastAPI / `127.0.0.1`）に届いていない。

**今後の報告の第一分岐（OS を先に決める）:**

| 相手 | 第一仮説 | 使うひな型 |
|------|----------|------------|
| **Mac・ログイン後 Connection Error**（UI は出る） | **瀧澤型:** v1.2.3 spawn 子 + HR + llvmlite JIT。ターミナル再署名では HR が残りうる → **v1.2.4-mac 再送** | `配布依頼メールテンプレート.txt` の **「Connection Error（Mac・第一返信）」**（v1.2.4 再送を約束可） |
| **Mac・起動前 SIGKILL**（ログイン未到達） | **前原型:** dist-info で codesign 失敗 | **v1.2.4-mac 再送**（上節） |
| **Windows**（電子カルテ端末・病院業務 PC） | ファイアウォール／プロキシがローカル待受を遮断 | 同ファイルの **「Connection Error（病院Windows）」** |

Mac の第一返信に病院PCの話を書かない。他施設名（尾花先生など）も書かない。**v1.2.3-mac 相手**には新 ZIP を約束せず再署名のみ。**v1.2.4-mac 以降**は `インストール.command` 付き ZIP の再送可。

**瀧澤型（ログイン後 Connection Error）— v1.2.3 ではターミナル codesign だけでは不十分なことが多い:**

1. クラッシュレポートに **Parent/Responsible: ARIAKE_OCTA [60050]**、**Process [60052]**（子）、スタックに **`libllvmlite.dylib` / `LLVMPY_TryAllocateExecutableMemory`** → 瀧澤型（spawn 子 + Hardened Runtime + numba JIT）。前原型（ログイン未到達・dist-info）と混同しない。
2. **v1.2.4-mac** を再送（スレッド起動・ad-hoc HR なし・dist-info 除去済み）。`インストール.command` を右クリック →「開く」。
3. v1.2.3 の再署名 2 行は前原型（dist-info）では **失敗**する。瀧澤型でも HR 付き v1.2.3 では JIT 問題が残る → **v1.2.4 再送を優先**。

## 6. GitHub 公開配布の運用

詳細は `documentation/DISTRIBUTION_REPO.md` を参照。

### 構成

| リポジトリ | 公開 | 内容 |
|-----------|------|------|
| `MNV_analysis_pro` | private 推奨 | ソース・ビルド |
| `ARIAKE_OCTA-distribution` | **public** | ZIP（Releases）・マニュアル |

### 日常運用

1. 本体でビルド → `MNV_analysis_pro` に Release publish
2. GitHub Actions（`Sync distribution repo`）が配布リポへミラー
3. 配布メールでは **distribution の Releases URL** を案内

### PAT（`DISTRIBUTION_SYNC_TOKEN`）とは

Actions が **別リポジトリへ書き込むためのトークン**。  
`MNV_analysis_pro` → Settings → Secrets → `DISTRIBUTION_SYNC_TOKEN` に Fine-grained PAT を登録。

### 手動同期（Actions が動かないとき）

## 8. Cursor / AI を使うとき

チャットで「配布依頼の返信文案」「〇〇先生の履歴更新」と依頼する場合:

1. `.cursor/rules/` は gitignore のため、**本手順書と `配布依頼メールテンプレート.txt` を `@` で指定する**
2. AI は `配布送付先・履歴.txt` と `配布依頼メールテンプレート.txt` を正とする
3. **出力はプレーンテキスト**（Gmail 貼り付け用。Markdown 表は使わない）
4. 送付後は必ず人間が履歴を確認・コミットする
5. **Mac の Connection Error** は病院PCから始めない。ひな型「Mac・第一返信」をコピペする。新しい ZIP を約束しない。他施設名を書かない

**依頼文の例**:
- 「飯田先生 OS 確認返信を受けた。履歴更新と Mac+Win 送付メールをテンプレ通り作成」
- 「鎌尾先生の解析成功返信を履歴に追加」
- 「寺尾先生へ再送。CC 津須先生。URL 案内版」
- 「東北大の瀧澤先生からログインできないとメールが来た。Gmail を見て、履歴と照合して、返信案を作って。」
- 「M1 の先生から Connection Error の報告。第一返信のひな型でドラフトして。」
- 「尾花先生と同じ接続エラー。Gmail を見て状況を整理して。」（内部メモ可。**宛先メールには尾花と書かない**）
