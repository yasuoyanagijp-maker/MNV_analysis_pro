# ARIAKE OCTA — 多施設グレーディングのご案内（GakuNin RDM）

**対象:** 各参加施設の読影担当者、および Team YY（中央読影）  
**文書の位置づけ:** 研究事務局から各サイト・Team YY への **協働通知**（運用設計の正本）  
**日付:** 2026-08-21  
**ボタン単位の操作手順:** [USER_MANUAL.md](../USER_MANUAL.md) §6A・§10.2〜§10.5

---

本アプリの二重読影は、**施設内で完結する経路**と、**GakuNin RDM を介して Team YY が第2読影を担う経路**の二本立てです。施設の読影者数に応じてルートが決まります。GakuNin 上では一般施設は自施設のデータだけを扱い、横断取得は Institution コード **`TEAM_YY`** に限られます。

---

## 1. この文書の目的

ARIAKE OCTA 多施設研究では、各観察時点の MNV 定量を **独立した 2 名の読影**で揃え、そのうえで治療前後の形態変化と関連因子を検討します。データ共有には **NII GakuNin RDM** を使います。

本書は、次の 2 つの立場に向けた **運用設計の通知**です。

| 宛先 | 本書で伝えること |
|------|------------------|
| **各参加施設** | 自施設での第1読影の進め方、読影者が 1 名のときに GakuNin へ上げるタイミング、施設内に 2 名いるときのローカル完結ルート |
| **Team YY（中央読影）** | 全施設の第1読影を横断取得し、第2読影・統合解析を行う手順。ログインコードは **`TEAM_YY` のみ** |

ボタン名やフォルダ選択の細部は [USER_MANUAL.md](../USER_MANUAL.md) を正とします。ROI の描き方は [roi_method.md](roi_method.md) を参照してください。

## 2. 研究上の読影設計

```text
観察時点ごとの定量（本アプリ）
        │
        ├─ 第1読影（施設グレーダー）
        ├─ 第2読影（施設内の第2リーダー、または Team YY）
        └─ 統合解析データ（RPD ≤ 20% → 平均採用、超過 → NA）
                │
                └─ NA（RECHECK）は最終読影者によるトライアッド中央値で確定
```

- **第1グレーダー**は原則として **自施設の症例**を読みます。  
- **第2リーダー**は第1と同じ病変セットを、**独立して** ROI から読み直します（第1のマスクを流用しません）。  
- 指標の一致は相対パーセント差（RPD）で判定します。

\[
\mathrm{RPD}=\frac{|A-B|}{(|A|+|B|)/2}\times 100
\]

| 判定 | 採用 |
|------|------|
| **RPD ≤ 20%**（両値が有限） | 算術平均を採用 |
| **RPD > 20%** または欠損 | **NA（再計測／合議）**。統合出力の `*_recheck_list.csv` を参照 |

NA になった主要指標は、Role **最終読影者** が再読影し、**G1・G2・最終読影者の 3 値の中央値**を確定値とします（詳細は USER_MANUAL §10.5）。

## 3. 施設の状況に応じた 2 ルート

| 施設の状況 | 使うルート | GakuNin |
|------------|------------|---------|
| **施設内に独立した読影者が 2 名いる** | **ルート A** — 同一端末または共有ディスク上の出力フォルダだけで完結 | **不要**（任意でバックアップ同期は可） |
| **施設内の読影者が 1 名のみ** | **ルート B** — 第1結果を GakuNin へ同期し、**Team YY が第2読影** | **必須** |

どちらのルートでも、採用ルール（RPD 20%）と成果物の種類は同じです。

## 4. 各参加施設向け（サイトグレーディング）

### 4.1 ログイン

1. **Researcher Name** はローマ字（CSV の Analyst / メタデータの `rater_id` になります）。  
2. **Institution code** は研究事務局から指定された **UPPER_SNAKE** コードを選びます（例: `ARIAKE_OHANACHAYA`）。一覧にない場合は **CUSTOM** に、指定コードを入力します。  
3. Role は作業に合わせて選びます。

| Role | いつ選ぶか |
|------|------------|
| **第1グレーダー** | 自施設の通常解析・第1読影 |
| **第2リーダー** | 施設内 2 名ルートで第2を読むとき、または自施設の第1データを GakuNin から取り直すとき |
| **最終読影者** | 統合後の RECHECK 症例を確定するとき（主に事務局／Team YY） |

**注意:** プルダウンの **「横浜市立大学」（`YOKOHAMA_CITY_UNIV`）は一施設のコード**です。中央読影の横断権限にはなりません。Team YY 作業では使いません。

環境変数 **`ARIAKE_INSTITUTION_ID`** が端末に入っていると、Export や第1同期のフォルダ名がログイン表示とずれることがあります。共有端末では env とプルダウンを揃えてください。

### 4.2 ルート A — 施設内に読影者 2 名（ローカル完結）

GakuNin を使わずに二重読影できます。

1. **第1グレーダー**が MNV 解析（ROI → 解析 → QC）を完了する。  
2. 結果画面で **この順**で実行する。  
   1. **Save CSV**  
   2. **Export Metadata & Data**（`export/images|masks|meta/{施設コード}/` と PDF）  
3. **ログアウト**する（同一端末で第2が続く場合。別端末なら出力フォルダ全体を共有）。  
4. **第2リーダー**・同じ施設コードでログインし、**「第2リーダー読影を開始（ローカル自動スキャン）」** で第1の出力フォルダ（`export` の親）を選ぶ。  
5. 各画像を独立して ROI → 解析 → QC する。  
6. **Save CSV** のあと **統合解析データ** を押す。採用値は同階層の `integrated_output_…/` に出ます。

```text
親フォルダ/
├── output_folder_YYYY_MM_DD/         ← 第1（CSV と export/）
├── second_reader_output_YYYY_MM_DD/  ← 第2
└── integrated_output_YYYY_MM_DD/     ← 採用値・recheck・summary
```

### 4.3 ルート B — 施設内読影者 1 名（GakuNin × Team YY）

自施設では **第1読影まで**を行い、第2は Team YY が担当します。

1. 自施設コード・**第1グレーダー**でログインし、通常どおり解析する。  
2. 結果画面で **Save CSV** → **Export Metadata & Data** を実行する（ローカルに成果物を残す）。  
3. **この時点ではログアウトしない。** 同じ結果画面の **「GakuNin RDMへ同期」** を押す。  
4. 初回のみ **Personal Access Token（PAT）** と project_id の入力を求められます。接続に成功すると PAT は OS の安全な領域に保存されます（メール・チャット・リポジトリに貼らないでください）。  
5. 完了メッセージ（件数・施設コード）を確認し、研究事務局へ **同期完了** を連絡する。  
6. ローカルの CSV / export は施設のバックアップ方針に従って保管する。**同期はクラウド複製であり、ローカル保存の代わりではありません。**

アップロードされるのは、結果画面が指す **`output_folder` 全体**です。リモート先フォルダ名は **`{institution_id}/`** です。

施設アカウントでも Role を第2リーダーにすれば、GakuNin から **自施設の第1データだけ**再取得できます。他施設は一覧に出ません。ローカルに第1出力が残っている場合は、ルート A の自動スキャンの方が速いことがあります。

### 4.4 各サイトがやってはいけないこと

- 他施設のデータを選ぼうとすること（アプリ側で一覧に出ません。正常です）。  
- 第1同期の前にログアウトして結果画面を閉じ、同期し忘れること（ルート B）。  
- Institution に **`TEAM_YY`** や **`YOKOHAMA_CITY_UNIV`** を選んで自施設第1を上げること。  
- PAT を共有アカウントのメモやソースコードに残すこと。  
- 統合後の **NA を手作業で平均値に置き換えて提出**すること（`*_avg_fallback.csv` / `*_triad_avg_fallback.csv` は参考・暫定です）。

## 5. Team YY 向け（中央グレーディング）

### 5.1 ログイン（必須）

横断取得・中央読影の Institution code は **`TEAM_YY` のみ**です。

| 使ってよい | 使ってはいけない |
|------------|------------------|
| **`TEAM_YY`**（プルダウン「Team YY（中央読影センター / OCTA-MIC）」） | **`YOKOHAMA_CITY_UNIV`（横浜市立大学）** — 施設アカウント。横断 ACL にならない |

Role は作業に応じて **第2リーダー**（通常の中央第2）または **最終読影者**（RECHECK 確定）を選びます。

### 5.2 第2読影の流れ

1. **`TEAM_YY`**・Role **第2リーダー**でログインする。  
2. ダッシュボードの第2リーダーカードで **「GakuNin RDMから第1読影データを取得して読影開始」** を押す。  
3. 一覧から **対象施設フォルダ**を選ぶ（全参加施設が表示されます）。  
4. ダウンロード後、自動で第2用スキャン／キュー投入が走ります。  
5. 各画像を **独立して** ROI → 解析 → QC する（施設第1のマスクは使いません。[roi_method.md](roi_method.md)）。  
6. **Save CSV** → **統合解析データ**。第1 CSV が取得ツリー内にあれば自動突合します。無い場合は、施設側が CSV ごと同期しているか確認してください。  
7. 採用値は **ローカル**の `integrated_output_…/` に出ます。  
8. 必要なら結果画面の **「GakuNin RDMへ同期」** で、**第2の `output_folder`（`second_reader_output_…`）だけ**を `second_reading/{施設コード}/` へ上げます。  
9. **施設を切り替える前に必ずログアウト**する（前回の graded / pending 施設 ID が残らないようにするため）。

### 5.3 同期されるもの／されないもの

| 操作 | リモート先 | 含まれるもの |
|------|------------|--------------|
| 施設・第1の「GakuNin RDMへ同期」 | `{institution_id}/` | 第1の `output_folder`（CSV と `export/` を含む） |
| Team YY・第2の「GakuNin RDMへ同期」 | `second_reading/{institution_id}/` | 第2の `output_folder` のみ |
| （同期ボタンの対象外） | — | **`integrated_output_*`（採用値・recheck・summary）は自動では上がりません** |

採用 CSV を共有する場合は、別途コピーするか、事務局が定めた手段を使ってください。再同期時、同名ファイルはスキップではなく **上書き更新**されます。

### 5.4 最終読影者（RECHECK）

統合で NA になった主要指標は、Role **最終読影者** で `*_summary.md` を選び、対象症例だけ再読影します。確定値は **median(G1, G2, 最終読影者)** です。手順は USER_MANUAL §10.5 および [triad_recheck/README.md](triad_recheck/README.md) です。

## 6. GakuNin RDM 上のフォルダ設計

アプリが想定するプロジェクト配下の配置です。施設コード名はログイン／同期に使う **UPPER_SNAKE** と一致させてください。

```text
GakuNin RDM（指定プロジェクト配下）/
├── {institution_id}/                      ← 第1グレーダー同期（施設が上げる）
│   └── （Save CSV と export/ を含む output_folder）
├── second_reading/
│   └── {institution_id}/                  ← 第2リーダー結果（Team YY または施設第2）
└── final_reading/
    └── {institution_id}/                  ← 最終読影の同期先（実装上の予約パス）
```

第1と第2を別パスにしているのは、**次の取得で第2結果が第1として混ざらないようにするため**です。

### 6.1 アクセス制御（アプリ実装）

| ログイン | GakuNin 取得で選べるもの |
|----------|--------------------------|
| 一般施設 | **自施設の第1読影フォルダのみ**。他施設は一覧に出ない |
| **`TEAM_YY`** | 参加施設の第1読影フォルダを **横断選択**できる |
| `YOKOHAMA_CITY_UNIV` | 横浜市立大学という **一施設**。Team YY と同じ権限にはならない |

project_id / folder_id はダッシュボードの **Advanced Settings**、または環境変数 `GRDM_PROJECT_ID` / `GRDM_FOLDER_ID` で保持します。値は研究事務局から配布します。

## 7. 事前準備（施設・事務局共通）

1. 研究事務局から **GakuNin プロジェクト（node）ID** と、必要ならルートの **folder_id** を受け取る。  
2. アプリの Advanced Settings に保存する。  
3. 初回の同期／取得時に **PAT** を入力する（OS の資格情報ストアへ保存。平文の `.env` コミットは想定していません）。  
4. 施設コードの表記ゆれ（半角スペース、小文字）はフォルダ不一致の原因になります。指定コードどおり入力してください。

## 8. うまくいかないとき（通知用・要約）

| 現象 | まず確認すること |
|------|------------------|
| 「自施設の第1読影データがありません」 | 第1が同期済みか。ログイン施設コードとリモートフォルダ名が一致しているか（`ARIAKE_INSTITUTION_ID` 優先にも注意） |
| Team YY なのに施設が一覧に出ない | Institution が本当に **`TEAM_YY`** か。`YOKOHAMA_CITY_UNIV` になっていないか |
| 統合解析データで第1 CSV が見つからない | 第1が Save CSV したファイルが同期／スキャン対象に含まれているか |
| 採用 CSV が GakuNin に無い | **仕様どおり**。同期は `output_folder` のみ |
| PAT を保存できない | OS のキーリング／資格情報ストアが使えるか |
| ログインで「Connection Error: All connection attempts failed」 | **GakuNin やパスワードの問題ではない。** 同じ PC 内の解析エンジンに届いていない。Mac で `CODESIGNING Invalid Page` なら現行配布が未公証のため（Windows 版へ）。病院業務用 Windows のファイアウォールでも同型の失敗あり |
| 別施設のパスに書き出された | 前回の Team YY セッションが残っていないか → ログアウトして再ログイン |
